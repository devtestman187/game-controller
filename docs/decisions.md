# Decisions

Architecture and tooling decisions, newest last. The PRD (`docs/PRD.md`) is the source of truth for requirements.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-24 | **Flutter/Dart** for both apps (Flutter 3.47.8 stable, Dart 3.13) | The only mainstream stack that covers Android, iOS, Android TV and Windows desktop from one codebase while keeping native iOS code to one small file, which matters with no Mac. |
| 2026-10-24 | **Dart pub workspace** at the repo root (`pubspec.yaml` → `workspace:`) | One `flutter pub get`, one lockfile, and the shared `protocol` package resolved by path. |
| 2026-10-24 | **State management: Riverpod** (`flutter_riverpod`, added in M1 when there is state to manage) | Testable without widgets, no code generation, and haptics, transport and sensors are easy to swap for fakes in tests (`ProviderScope(overrides: ...)`). |
| 2026-10-24 | **Protocol: JSON text frames over WebSocket**, envelope `{"v":1,"t":"type",...}`, sealed Dart classes | Easy to debug and log. JSON at ~60 Hz is small. The version field detects mismatched builds, and unknown types are ignored for forward compatibility. `hello` carries `controllerId`, so multiple controllers work without a redesign. UDP for gyro only if M6 latency measurements require it. |
| 2026-10-24 | **Transport:** `dart:io` HttpServer/WebSocket (TV side), `dart:io` WebSocket (phone side) | Same code on Android TV and Windows, no extra packages, TCP_NODELAY settable on the upgraded socket. |
| 2026-10-24 | **Discovery: `bonsoir`** (mDNS/DNS-SD, service `_gamectl._tcp`) | pub.dev lists Android, iOS, macOS, Windows and Linux. Windows advertising is verified at the start of M1, with manual IP entry as the fallback. |
| 2026-10-24 | **App IDs** `com.gamecontrollerdev.controller` (phone, Android + iOS) and `com.gamecontrollerdev.tvtest` (TV) | Chosen once. Free Apple IDs allow only ~10 new bundle IDs per week, so these never change. Nothing ties them to a paid account, so TestFlight later is unaffected. |
| 2026-10-24 | **Minimum versions:** phone Android 16 (minSdk 36), iOS 26.0, TV minSdk 31 (Android TV 12) | PRD decision (Oct 23, 2026). |
| 2026-10-24 | **CI split:** GitHub Actions (Ubuntu/Windows) for analyze, test and Android/Windows builds; **Codemagic** for unsigned iOS only; GitHub Actions macOS = manual fallback | Saves the ~500 free Codemagic macOS minutes per month for iOS. The repo is public, so GitHub Actions minutes are free. |
| 2026-10-24 | ~~**Sideloadly** is the standard iOS install tool; AltStore is documented as optional auto-refresh~~ (superseded below) | PRD open question answered. It was the simplest way to start. |
| 2026-10-24 | iOS uses **Swift Package Manager** (Flutter default), so there is no Podfile. The deployment target is set in `Runner.xcodeproj` | Flutter 3.47 template default. The CocoaPods cache stays configured in CI in case a plugin needs it. |
| 2026-10-24 | **/assets is a Flutter package (`game_assets`)** | Flutter can't bundle files from outside an app's folder. Both apps depend on this package, and assets are looked up by logical key through `lib/asset_manifest.dart`. |
| 2026-10-24 | TV manifest declares `leanback` and `touchscreen` as **not required** | The app still shows in the TV launcher (LEANBACK_LAUNCHER + banner) but can also be sideloaded on emulators for quick checks. |
| 2026-10-24 | **iLoader** replaces Sideloadly as the iOS install tool. Only Apple's iTunes is needed on the PC (no iCloud). The build is re-installed by hand every 7 days | PRD update: iLoader signed in and installed when Sideloadly and Impactor failed. SideStore auto-refresh is still a PRD open question. |
| 2026-10-24 | M0 closed with the **Android phone install test deferred** | User decision: test M1 on the iPhone first. The phone APK still builds in CI, and the Android phone checks get run later. |
| 2026-10-24 | **`packages/connection`** (pure Dart) holds the host server, the phone client and the simulated controller, instead of a separate `packages/sim_controller` | The same code runs in both apps, the CLI and `dart test` on Windows/CI. The pairing, heartbeat and reconnect logic is tested with real sockets on localhost. |
| 2026-10-24 | **Pairing:** 4-digit code on the TV. A correct code gets a random **token** per controller, which the phone saves per host ID and uses for reconnects. 5 wrong codes in a row change the code | Short to type, and reconnects need no code (PRD "reconnect without manual steps"). Tokens live in TV memory, so a TV app restart asks for the code again (restart recovery is M6). |
| 2026-10-24 | **Port 45780**, WebSocket path `/ws`, falling back to a free port if it's taken. The TV binds dual-stack (IPv6 with IPv4) | A fixed port makes manual entry and firewall rules simple. The fallback port is advertised and shown on screen. |
| 2026-10-24 | **Heartbeat:** `ping`/`pong` every 1 s from both sides, 4 s silence = dropped. Phone retries 0.25, 0.5, 1, 2, then every 3 s | Fast enough to notice a Wi-Fi drop, light enough for the ~60 Hz gyro stream later. |
| 2026-10-24 | **`bonsoir` 7.1.5** for mDNS on Android, iOS and **Windows** (advertising verified on this PC with an mDNS query on 2026-10-24) | PRD asked to check Windows support early. Manual IP entry stays as the fallback. |
| 2026-10-24 | **iOS local network status is inferred** (found a TV = allowed, "No route to host" (errno 65) to a LAN address = probably denied) | iOS has no API to read it, and checking natively would add Swift. |
| 2026-10-24 | **`shared_preferences`** for the controller ID, tokens and last TV (phone) and the host ID (TV). **`share_plus`** for "Share log" | Well-established plugins with no custom native code. |
| 2026-10-24 | M1 closed. Ping spikes over 100 ms seen on the iPhone: attributed to phone Wi-Fi power saving with sparse traffic (TCP_NODELAY is already on in Dart's HTTP stack). M2 adds lowest/average/highest ping over 30 s on both screens | User's choice, to measure before M6's latency work. |
| 2026-10-24 | **Input as full state** (`input` message: seq, buttons, dx, dy) on every change, not separate down/up events. Protocol stays v1 (older peers ignore the new type) | Makes stuck buttons impossible by design: the latest message is the truth and an empty state releases everything. Edges are easy to derive on the TV. |
| 2026-10-24 | **8-way D-pad** with 60° for straight directions and 30° for diagonals, a center dead zone, and sliding without lifting. Face buttons accept sliding from one to the next | Straight directions matter most in simple games; sliding is how thumbs play on glass. |
| 2026-10-24 | **Native haptics in the app, not a plugin**: Swift in `AppDelegate.swift`, Kotlin `Haptics.kt` | PRD C7 asks for Core Haptics and VibrationEffect behind one interface. Keeping the Swift in an existing file avoids editing the Xcode project without a Mac. |
| 2026-10-24 | Android haptics use the **click primitive** with usage **media** | Crisper than a one-shot buzz, and "media" (which covers games) isn't silenced by the system touch-feedback switch. |
| 2026-10-24 | Haptic on/off and intensity are **saved** already in M2 | A one-line use of shared_preferences. The full Settings screen stays in M6. |
| 2026-10-24 | M2 closed: user confirmed on the iPhone and the TV ("haptics and responses feel solid on iOS") | Android phone still deferred. |
| 2026-10-24 | **Gyro tilt = complementary filter** (gyroscope + accelerometer via `sensors_plus` 7.1.1) estimating the up direction, not raw gyro rates | Raw rates integrate into drift, and the accelerometer alone is jittery from hand movement. The filter is pure Dart and testable on Windows, with no native code. |
| 2026-10-24 | Full deflection at **30° × 1/sensitivity**, sensitivity 0.5–2, dead zone 0–30% (default 5%, round and rescaled), smoothing 0–90% (default 50%), all saved | A comfortable steering range. The settings map directly onto the PRD's C4 controls. |
| 2026-10-24 | **Screen locked to the current landscape side in gyro mode** | Tilting to steer would otherwise rotate the UI and flip the axes. If the side guess is wrong, the UI turns once and the axes then match how the phone is held. |
| 2026-10-24 | Tilt travels in the same `input` message as optional `ax`/`ay` fields (3 decimals), protocol still v1 | Buttons and tilt stay in one consistent state, and older TVs ignore unknown fields. |
| 2026-10-24 | iOS needs **NSMotionUsageDescription** in Info.plist | sensors_plus crashes the app on motion access without it. |
| 2026-10-24 | **M3 fix (0.3.1): the gyro screen lock uses the opposite landscape name on iOS**, and the held side is tracked in D-pad mode too | The user saw the screen turn 180° on every D-pad/Gyro switch on the iPhone. Flutter's `landscapeLeft`/`landscapeRight` follow Android, and on iOS they map to UIKit's interface orientations, whose left/right are reversed. Android keeps the Flutter names (not yet confirmed on a device). |
| 2026-10-24 | **M3 fix (0.3.2): reset the tilt filter on every sensor start, settle about 0.3 s, then calibrate**; the lock side comes only from the debounced side tracker | The user saw the dot drift off-center when starting gyro mode with the phone flat, and the 180° turn still happened about once in 20–30 switches. Both came from the filter keeping its estimate from the previous gyro session: the center was calibrated on an old position, and the lock side could be read from it. |
| 2026-10-24 | **Milestones renumbered (PRD update):** new M4 analog stick mode (Xbox-style: two sticks, D-pad, A/B/X/Y, LB/RB, LT/RT, View, Menu); TV-to-phone haptics and the test game move to M5; polish, settings and latency move to M6 | So the test game and the polish milestone cover all three input modes. Rows above that say "M5" for latency, settings or restart recovery were updated to M6. |
| 2026-10-24 | M3 closed: user confirmed with 0.3.2 (`m3.2`) on the iPhone and the TV | Android phone still deferred. |
