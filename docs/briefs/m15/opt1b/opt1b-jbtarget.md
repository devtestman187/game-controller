Design (page side; keep new code in a NEW small module streaming/player/jb_target.js; reporter.js and player.js get only a few lines each):
1. Option `jbtarget=<ms>` through the existing options.js (URL query or SESSION_PLAYER_OPTIONS; bench `--player-query` already passes it; it combines with `marker=1`, `lowdelay=1`). Pure `jbTargetOf(options)` returns the integer ms when the value is a whole decimal number 0..4000 (no sign, no decimals, no empty, no "1e2"), else null (ignored: the page behaves exactly as without the option). A bare `?jbtarget` becomes "1" in options.js, so it is the number 1, not "on": say so in a comment.
2. Class JbTarget (only created when jbTargetOf is not null): `watch(pictureConnection, soundConnection)` applies at once to every RTCRtpReceiver of both connections (video and audio) and then every second until `stop()`, as LowDelay does; apply = if `'jitterBufferTarget' in receiver` set it, in try/catch (record the first error text, never throw). It is called wherever the page already calls lowDelay?.watch AND from pictureReady / soundReady and the track events, so a receiver is set as soon as it exists and again after any reconnect. `state()` returns {requested, supported (yes when every receiver has the property, "no" when none has it, "partial", "none yet" when no receiver exists yet), applied (the value READ BACK from the receivers at that moment: one number when all agree, else the values joined by "/", "missing" when absent), error (first error text or "")}. The read-back happens each time state() is called, never cached.
3. When both `lowdelay=1` and `jbtarget` are on, the jbtarget value wins: low_delay.js must not set jitterBufferTarget (its playoutDelayHint etc. stay) when jbtarget is on, and JbTarget applies after it. tuneForLowDelay in player.js runs once at pictureReady/soundReady: JbTarget must apply after that too. Without jbtarget, low_delay.js and tuneForLowDelay behave exactly as before.
