Everything the probes proved exists only as hand-made state inside the distro. This job makes it **reproducible from the repository**. Claude's design:
1. **The Linux runner** for `tv_test_app`: generate it in the distro copy (`flutter create --platforms=linux .`), then bring the generated `tv_test_app/linux/` files into the repository (read each with a `wsl ... cat` command and write it with Edit; they are small text files), with the window titled "Thumb Party TV" and a default size of 1920×1080 when the environment asks for it (see 3). The Windows and Android builds must be unchanged. Do **not** bring the probe's debug-flag patch (job a2 replaces it with the automation interface).
2. **`streaming/`** (new top-level folder) with:
   - `Dockerfile` (multi-stage, pinned versions, comments saying why each pin): a build stage for the Flutter Linux release bundle of `tv_test_app`; a build stage for gst-wayland-display at the pinned commit (and the libwayland it needs) and for `webrtcsink` + its signalling server from gst-plugins-rs at a pinned version; a slim runtime stage with GStreamer, PulseAudio, the plugins, the bundle and the scripts. No secrets, no root-owned junk; a non-root user for the game if the GPU access allows it (say if not).
   - `entrypoint.sh`: start PulseAudio with a null sink; start the pipeline (`waylanddisplaysrc` → convert → `nvautogpuh264enc` with explicit low-latency settings: no B-frames, zerolatency-style preset, CBR at a bitrate from an env var with a sane default (10 Mbit/s), GOP/keyframe interval set, and confirm in the log that the bitrate is honoured, since the probe saw it ignored; sound from the sink monitor → Opus) into `webrtcsink`; start the signalling server and a tiny static web server for the player; start the game as the compositor's client; forward signals and exit codes; write a `ready` line to the log when the game window is up and the pipeline is PLAYING. Everything configurable by env vars with defaults (resolution, frame rate, bitrate, ports, encoder element).
   - `player/`: a minimal **web player** page (plain HTML + JS, no build step) using gst-plugins-rs's own `gstwebrtc-api` client to connect to the signalling server, play video and sound full-screen with the lowest-latency settings the browser allows (`jitterBufferTarget`/`playoutDelayHint` 0, no controls, autoplay with a "tap to start sound" fallback), show a small toggleable overlay (resolution, fps, bitrate, round trip, jitter buffer, decode time, dropped frames from `getStats`), and reconnect on drop. Keep the stats collection in one small module: job c2 extends it to report to the host.
   - `README.md`: what each piece is, the ports, the env vars, how to build and run by hand.
