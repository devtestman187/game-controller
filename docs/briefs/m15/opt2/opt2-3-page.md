This job is page-only and runs beside the host jobs: code against PROTOCOL.md; do not touch streaming/tap, serve.py, entrypoint.sh or the Dart packages.

Design (new code in NEW small modules; player.js and index.html get only a few lines each; no function over 60 lines; player.js is 398 lines now and must end at or under 380: moving code OUT of it into the new modules is part of the job):
1. options.js: pure `playerKindOf(options)` returning "wc" only when `player` is exactly "wc", else "webrtc". Default behaviour unchanged.
2. streaming/player/wc_annexb.js (pure; same script/module style as the other player files): `splitNalus(bytes)`, `nalType`, `isKeyframe(bytes)`, `parseHeader(arrayBuffer)` per PROTOCOL.md (returns {flags, keyframe, discontinuity, frame, ptsUs, sentUs, payload}), `codecString(sps)` (avc1.PPCCLL), `buildAvcc(sps, pps)` (AVCDecoderConfigurationRecord, lengthSizeMinusOne 3), `annexbToAvcc(bytes)` (start codes replaced by 4-byte lengths; AUD, SPS and PPS NALs dropped from the sample; slice NALs kept). Decision to take and report: AVCC with a description is the default decode mode (the study's safe choice); add Annex B mode (no description, in-band SPS/PPS) selectable by page option `wcmode=annexb`; say in the report which is the default and why.
3. streaming/player/wc_player.js: class WcPlayer with constructor options {url, canvas, onEvent, onDrawn, now, WebSocketImpl, VideoDecoderImpl, EncodedVideoChunkImpl, setTimeoutImpl} (the injections are for the tests; defaults are the browser globals) and start()/stop(). It opens a WebSocket to `ws://<location.host>/tap` (binaryType arraybuffer). On each binary message: parse the header; on a keyframe (re)configure the VideoDecoder when the SPS/PPS changed or it is not configured yet (`codec` from the SPS, `description` = avcC, `optimizeForLatency: true`, `hardwareAcceleration: 'prefer-hardware'`; if isConfigSupported says no, retry without the hardware hint and record which config was used), then decode one EncodedVideoChunk per message ("key" or "delta", timestamp = frame number * 1000 so it is unique and increasing). Delta frames before the first keyframe, and frames after a gap in frame numbers (unless the frame is a keyframe), are dropped and `{"type":"key"}` is sent (at most one per 500 ms). The decoder output callback draws the VideoFrame onto the canvas (2d context `drawImage`; canvas sized to displayWidth/Height; `desynchronized: true` context option where supported) then ALWAYS `frame.close()` (finally). Keep `decoder.decodeQueueSize` at most 2: a frame that arrives with the queue above 2 is dropped and counted, and a keyframe requested (after any drop the next delta frames are discarded until a keyframe). A decoder error: close it, reconfigure at the next keyframe, request a keyframe. Socket close or error: reconnect with backoff 200 ms doubling to 2 s while the page is open; a text `{"type":"end"}` shows the page's usual "stream ended" state (reuse session_end.js / page_state.js) and stops reconnecting. `counters()` returns plain numbers: framesReceived, framesDecoded, framesDrawn, dropsQueue, dropsGap, keyRequests, decoderErrors, reconnects, queueMax, lastFrame, plus text `decodeConfig`. Per frame it also records receiveAt (when the message arrived), decodeOutputAt (decoder output callback) and drawnAt (after drawImage), all `now()` (performance.now) values, kept for the last 256 frames keyed by frame number, readable through `stageSamples()` (job 4 turns them into figures), and it calls `onDrawn(frameNo, drawnAt)` after each draw (job 4 reads the marker there).
