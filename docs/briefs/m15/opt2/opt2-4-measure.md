Design:
1. Marker on the canvas: with `player=wc` and `marker=1`, marker_reader reads the strip from the canvas (drawImage source = the canvas, or getImageData of the strip rows) right after each draw (use WcPlayer's `onDrawn(frameNo, drawnAt)`); no requestVideoFrameCallback on a canvas. The marker's frame counter and `performance.now()` after the draw give the display time; a sample is the same record the video path produces. Keep the video path byte-for-byte as it is. Read cost must stay small (only the strip's rows, getImageData with willReadFrequently where relevant).
2. Press-to-screen (card/probe flips): find what the current press probe (latency_probe.js, the flip detection) reads from the video element and make it read the canvas with `player=wc`, so the card measurement works as today. Press and controller input untouched.
3. New stage figures in a new module streaming/player/wc_stats.js (pure + small): from `stageSamples()` compute over each reporting interval medians (and p95 where the existing tables do) of receive-to-decode-output ms and decode-output-to-draw ms; plus counters: dropped frames (dropsQueue+dropsGap), WebSocket backlog (frames received but not yet drawn; also the largest gap `lastReceiveAt` to now), keyframe requests, decoder queue size (max in the interval), and a best-effort "hardware" fact (decodeConfig text says prefer-hardware accepted, or `unknown`; never claim more than that). Report them through the reporter's existing extra facts/gauges provider (same way as jb_target.js): gauges `wcRecvToDecodeMs`, `wcDecodeToDrawMs`, `wcDropped`, `wcBacklog`, `wcKeyRequests`, `wcQueueMax`; fact `wc` = text like `cfg=hw dec=ok` within the host's fact limits (check them). With the option off nothing new is sent. The overlay shows one line only with player=wc.
