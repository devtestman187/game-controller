Why in-process: gst-launch cannot hand buffers to Python and a force-key-unit event must reach the encoder. So with SESSION_TAP=on the entrypoint starts `python3 /usr/local/bin/tap/tap_runner.py -- <the same argument list build_pipeline builds, with the tap branch added>` instead of gst-launch. Use `Gst.parse_launchv(argv)` (list form; same token semantics as gst-launch; verify in the distro that webrtcsink and the other arguments parse identically). Behave like `gst-launch -e`: on SIGTERM/SIGINT send EOS, wait for the EOS message up to 5 s, then set NULL. Keep GST_TRACERS/GST_DEBUG env as they are so pipeline.log still gets the latency records.

Design:
1. Entrypoint: switch SESSION_TAP (default off; warn and run off on a bad value, like SESSION_MARKER). When on, the tee goes right AFTER the encoder: `<encoder ...> ! tee name=t  t. ! h264parse config-interval=-1 ! webrtcsink ...` (the existing branch, no queue added to it) and `t. ! queue leaky=downstream max-size-buffers=2 max-size-time=0 ! h264parse config-interval=-1 ! video/x-h264,stream-format=byte-stream,alignment=au ! appsink name=tap drop=true max-buffers=2 sync=false emit-signals=true`. The sound branch refers to `ws.` and must keep working in all three SESSION_AUDIO modes. `tap_port` = ${TAP_PORT:-$((automation_port + 1))} is computed and passed to the runner as --port (the server is job 2; here the runner exposes callbacks, see 3). Off: the command line is exactly as today.
2. streaming/tap/tap_frames.py (pure, no GStreamer import): `pack_header(flags, frame, pts_us, sent_us)` per PROTOCOL.md; `split_nalus(annexb)`, `is_keyframe(annexb)` (IDR NAL type 5), `extract_sps_pps(annexb)`, `profile_string(sps)` giving avc1.PPCCLL, `frame_size(sps)` (width, height from the SPS, with frame cropping, enough for the baseline/main/high profiles the encoder makes).
3. streaming/tap/tap_runner.py: parse args, Gst.init, build the pipeline, hook the appsink `new-sample`: pull, copy bytes, flags, PTS in microseconds, a frame counter counting every sample; call each callback in `on_frame` list as `cb(frame_no, pts_us, is_key, data)` (job 2 plugs the server in); keep `info` (profile string, width, height, whether SPS/PPS repeat on every keyframe counted over the first keyframes, whether any buffer had DTS != PTS i.e. reordering). `request_key_unit()` pushes `GstVideo.video_event_new_upstream_force_key_unit(Gst.CLOCK_TIME_NONE, True, 0)` onto the appsink's sink pad, at most once per 200 ms. Run a GLib.MainLoop. Errors go to stderr so the entrypoint's log shows them. The appsink callback stays fast (no I/O except the callbacks). An optional `--on-frame-module` is not needed: job 2 edits the runner to start the server.
4. Dockerfile: ONE added apt line group in the runtime stage: `python3-gi gir1.2-gstreamer-1.0 gir1.2-gst-plugins-base-1.0` (owner-approved, inside the image build file only; nothing else) and a COPY of streaming/tap/ to /usr/local/bin/tap/ (the image copies streaming/player the same way). Do NOT run a build (the main session does).
