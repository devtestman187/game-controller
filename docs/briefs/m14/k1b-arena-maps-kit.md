The owner asked for four Arena maps and a kit for them, and for that kit to be Shape Race's, not a second one. k1a made the kit general; this job adds maps as its second kind, with today's field as the first map. No new piece (springs, belts) and no new map yet: those are k2. Claude's design:
1. **The map file** (`packages/test_game/maps/<id>.json`, listed in `maps/index.json`, `_template.json`, `map.schema.json` with a description per field), using the shared header (`$schema`, `format: 1`, `id`, `name`, `notes`). Fields, in fractions of the 16:9 field as today: `line` (one line for the picker), `theme` (only `"playroom"` for now; k2 adds others), `walls` (`from`, `to`), `hazards` (`slide` with `from`, `to`, or `orbit` with `centre`, `radius`; each with `periodS` and optional `phase`), `race` (`start`, `goal` rect, `swapSides`: rounds alternate as today) and `bumper` (`starts`: four spots; `coins`: one or more rects where coins may appear). `race` or `bumper` may be left out; at least one is needed.
2. **`playroom.json` is today's field** (the walls, hazards, start, start spacing and goal now in `arena_field.dart`), plus a `bumper` section you design: four starts and coin zones that pass every rule below. A Dart `ArenaMap` type parses a file with the shared core's messages; an `ArenaMapLibrary.load()` reads `maps/` from the bundle like `PuzzleLibrary.load()` (assets in `test_game/pubspec.yaml`).
3. **The game takes a map.** `ArenaFieldRules`/`ArenaGame` take an `ArenaMap` instead of the wall and hazard lists and the start/goal constants. Until the waiting card loads maps (job b2), `ArenaGame()` with no map uses `ArenaMap.playroom`, a const in code; a test pins that `playroom.json` parses to exactly that const and to today's numbers, so the two cannot drift. Behaviour is identical: every existing arena, host and tv test passes (changes to how a test builds a game are fine, nothing else).
4. **`arena_field.dart` under 300 lines** (it is 391): the constants and default lists leave it for the map; split further by content if needed.
5. **The map rules** (`map_rules.dart`, parts as `puzzle_rules` has them), returning `LevelIssue` with a `MapRule` enum, each message naming the map and the part and saying what to change:
   - everything inside the field;
   - every gap a marble must pass is at least 2.5 marbles wide;
   - race: start (with every extra start at the start spacing, for four players) and goal clear of walls; a path from each start to the goal, both ways when `swapSides`; no hazard's sweep (its whole path, grown by its radius) touches a start or the goal;
   - bumper: four starts, clear of walls, at least 3 marble diameters apart, outside every hazard's sweep; each coin zone clear of walls and reachable from every start, with room for at least 3 coins together;
   - no free area a marble could stand in but never reach from a start;
   - limits: at most 24 walls and 8 hazards; no hazard faster than one pass every 1.5 s;
   - the snapshot with this map and four marbles is under the 2048-byte budget with 300 bytes kept for the Bumper Round's coins (a named constant b1 replaces with real coins).
   Reachability uses one **path grid** (`MapGrid`): the field in cells of about a fifth of a marble, walls grown by a marble's radius, with a flood fill and a shortest path between two points. Public and tested on its own: Robo (job b3) will steer with it.
6. **`tools/level.sh` for maps**: `new map <id> [--name "Name"]` (from `_template.json`, added to `maps/index.json`), `check` with no id runs puzzles and maps, `check <id>` finds the kind, an id used by both is an issue (the core has it), `render <id>` writes `docs/design/maps/<id>.png`: the field in Sunny and Night with the starts, goal and coin zones marked and each hazard's sweep drawn faintly. The template passes `check` unchanged.
7. **docs/levels.md's Arena part**: the field's coordinates with a small diagram, each field of a map, the two modes' needs, the map rules with one example message each, and the shared workflow. docs/dev-tools.md's `tools/level.sh` section names maps too.
