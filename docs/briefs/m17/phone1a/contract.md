# phone1a contract: the generic phone "choices" screen, host and protocol side (M17a, B5)

Owner, Nov 26: "Build, 1A 2A"; "I'm ok with all recommendations": the generic choices screen behind a new hello cap ships in M17a; old phones keep playing through the A/B/X/Y fallback. No protocolVersion bump (it would close old phones with code 4000). No slot-7 colour. The screen is NOT a GameModule (view_start goes to every phone). The phone UI is B6 (y0d); no phone lists `Capability.choices` yet, so after B5 the feature is dormant on real phones.

## Wire (y0a), packages/protocol/lib/src/choices.dart, a part of messages.dart
- `Capability.choices = 'choices'`. A host lists it in its welcome (host_service.dart:144, y0b); a phone lists it in its hello (B6). A side only sends a message the other side listed.
- `ChoiceCard`: `id` (non-empty String), `title` (cut to 24 chars), `detail` String?, `cost` int? (per unit), `maxCount` int (1..9, default 1; above 1 the card is counted: "Build 3"), `enabled` bool (default true; false = shown greyed, cannot be picked). toJson/fromJson/==/hashCode like NightAwardRow (night.dart).
- `ChoicesMessage` wireType `choices`, host to phone: `round` int, `title` String, `cards` 1..6 `ChoiceCard`s (unique ids), `endsInMs` int (time left when sent; the phone counts down on its own clock), `defaultId` String? (a card id; applies when nothing is chosen), `currency` String? (e.g. "Bolts"), `picked` String? and `pickedCount` int (default 1) and `locked` bool (what the host already has for this player: a resend after a reconnect shows it).
- `ChoicePickMessage` wireType `choice_pick`, phone to host: `round` int, `pick` String? (null = clear), `count` int (default 1), `locked` bool.
- `ChoicesEndMessage` wireType `choices_end`, host to phone: `round` int, `result` String? (the card the host applied), `count` int, `byDefault` bool.
- A decode error is a FormatException (as every codec message); unknown extra fields are ignored.

## Host round (y0b), packages/connection/lib/src/choice_round.dart (new), exported from connection.dart
`ChoiceRound` is plain Dart over a `HostServer` (no GameHost change: three classes implement GameHost, FakeGameHost in party_host/testing too). Constructor named args: `server`, `round` int, `title`, `cardsFor` (`List<ChoiceCard> Function(String playerId)`; roadworks exists only in the last place's list), `players` (player ids), `duration`, `grace` (Duration), `defaultId`, `currency`, `nowMs` (`int Function()`).
- `start()`: sends `ChoicesMessage` (current state, `endsInMs` from the clock) to each player whose session lists the cap, through `server.send` (it returns false for a phone without the cap: that player is "legacy" and is never sent a choices message). Starts the end timer (`Timer(duration, close)`).
- `pick(playerId, {String? pickId, int count = 1, bool locked = false})`: ignores an unknown player or a card the player's list lacks or that is disabled; clamps `count` to 1..maxCount; stores it; fires `changes`. Used by a phone's `ChoicePickMessage` (ignored when the round id differs, the sender did not list the cap, or the round is closed) and by the old-phone fallback (y0c).
- Undo: a pick with `locked: false` (or `pickId: null`) is accepted until the timer ends; there is no hard lock.
- Reconnect: when a player's session is connected again (HostServer.changes), resend the current state with `picked`/`locked`.
- Away: a player not connected for `grace` is set to the default (locked, `byDefault`) and stays so until a pick changes it.
- `close()` (the timer, or called early; idempotent): each player's outcome is the stored pick if there is one (locked or not), else the card `defaultId` ("Save +2" for the shop; null `defaultId` = Vote abstains); sends `ChoicesEndMessage` to each capable phone; returns `Map<String, ChoiceOutcome>` (`cardId` String?, `count`, `byDefault`); `changes` fires. `lockedIds` and `outcomes` getters; `dispose()` cancels timers.
- `HostServer.capabilityFor` maps `ChoicesMessage` and `ChoicesEndMessage` to `Capability.choices` (y0a); a `ChoicePickMessage` from a session without the cap is ignored (y0a).
- Assumption to confirm with the owner: a picked but not locked card counts at the timer end (lock-in only confirms).

## Old phones (y0c), packages/connection/lib/src/choice_fallback.dart (new)
One function `oldPhoneButtons(List<ChoiceCard> cards)` holds the whole mapping (swap it here only; owner decision O3 default, Nov 26): the cards in order take A, B, X; Y is "Clear" (back to nothing chosen); with 4 cards the 4th takes Y and there is no Clear. A card with `maxCount > 1` is counted: each not-held-to-held change of its button adds one, up to maxCount. Unused buttons are hidden with `GameLayoutMessage.hidden`. Labels are cut to 12 chars (`GameLayoutMessage.maxLabelLength`); status text is at most 24 chars (`StatusMessage.maxTextLength`), e.g. "Build 3 = 9 Bolts" (title, count, count x cost, currency), "Save +2", nothing chosen: "Default: <title>". The old phone's choice is only stored with `locked: false`, so it applies at the timer end. At `close` the layout goes back to `GameLayoutMessage.standard()` and the status to `StatusMessage.hidden()`.
Probe (Nov 26, thumb-haiku): the phone pad sends every button change at once (pad.dart:143-145), with no debounce or auto-repeat, and the host forwards every newer seq (host_connection.dart:258-265), so counting not-held-to-held changes per InputStateMessage is exact.
