why: Claude checks by hand that a move or refactor didn't change any message, log line or UI text, by comparing the string literals before and after. This automates it.

do:
1 `tools/review.sh --strings [--base <ref>] [--head <ref>]`. Old side: the `.dart` files under any `lib/` or `bin/` folder that differ between base (default HEAD) and head, as they are at base. New side: the same files as they are at head (default the working tree, untracked `.dart` files included). Files added or deleted count, with an empty other side. `--head` is only valid with `--strings`; `--strings` with `--all` is an error (exit 2).
2 Compare the string literals of the two sides as one multiset each (not per file), so a string that moved to another file counts as unchanged. Print the differences, then a totals line:
   `- 'text'  file` for a literal only on the old side (the file it was in at base)
   `+ 'text'  file:line` for one only on the new side
   `strings: <n> removed, <n> added, <n> unchanged or moved`
   Sort the - lines, then the + lines, each by file and line. Exit 0 (it's information, not a FAIL), 2 for bad arguments.
3 What counts as a literal: single- and double-quoted strings, raw (`r'…'`) included, printed as written in the source (quotes and `$x`/`${…}` kept, so a renamed interpolated variable shows as - and +). Quotes inside `${…}` belong to the outer literal. Each line of a `'''`/`"""` string is one literal. Skip: comments (`//`, `///`, `/* */`) and `import`/`export`/`part`/`library` lines. Adjacent literals are separate.
4 Put the extraction in a new `tools/review-strings.awk` (one literal per output line: `file<TAB>line<TAB>text`), called by review.sh, to keep review.sh under 400 lines. Use git show/diff for the base and head sides (no checkout, no temp worktree).
5 docs/dev-tools.md: add `--strings` and `--head` to the review.sh section in the same style, with one example: `tools/review.sh --strings` before committing a pure move.
6 Prove it on history (put the outputs in the report, cut to 40 lines each):
   a `tools/review.sh --strings --base 52cf0ea~1 --head 52cf0ea` (step 2 G3, a pure move: expect only - and + pairs from renamed interpolated variables, if any)
   b `tools/review.sh --strings --base 52cf0ea --head 46e142b` (step 2 G4: expect the new local-player texts and the changed "could not start" text)
   c `tools/review.sh` and `tools/review.sh --all` totals lines: the same before and after your change.
