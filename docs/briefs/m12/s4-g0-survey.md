## Constraints

- The app has no library file; tests import `package:controller/src/...` (`layout_test.dart:3`, `tilt_test.dart:1`), so moved types keep those paths or the tests move with them.
- Keys the tests find and a split must keep: `faceButtons`, `dpad`, `leftStick`, `rightStick`, `faceButtonLabels`, `pressFlash`, `statusPanel`, `statusShape`, `statusText`, `statusProgress`, `pingStats`, `connectionChip`, `playerBadge`, `inputSummary`, `tiltView`, `tiltValues`, `calibrate`, `tooSmall`, `demoReadout`, `settings*`, `stick*`.
- Persisted keys in answer 5 are asserted by tests (`settings_test.dart:51-89`, `tablet_and_feedback_test.dart:39-65,225`, `stick_mode_test.dart:98`); new settings follow the same `load`/`save` + clamp pattern.
- Layout rules the tests enforce: no overlap and on screen at every button size, A/B/X/Y never above the setting, touch areas never stolen (`layout_test.dart` 105 cases), control rects unchanged when layout or status arrives (`game_controls_test.dart:83`).
- Metrics mirror the layout: `touchMapFor` `phone_metrics.dart:182-` recomputes the same rects in mm from the body box set in `controller_screen.dart:133-140` (below the top bar), and `metricsSettings` `:149-175` records `buttonSize`; a layer over a game changes the body and the recorded millimetres.
- Wire: `layout` and `status` are host→controller messages gated by capabilities; step 4 needs no wire change unless a "game is shown" flag travels (additive, gated).

## Conflicts

1. §4 puts `overlayOpacity` (0.2–1.0, default 0.6) in `HostingSettings` (`hosting_settings.dart:4-40`: no such field, no storage, only a `ranges` map `:39`), but §2.7 says it is saved "with the other settings" — the phone's settings live in `controller_app`, whose pubspec does not depend on `game_kit`.
2. §2.7's `ControlsLayer(opacity)` over "any child" has no child slot today: the controls are the `Scaffold` body and the top bar, connection chip and status panel sit above them (`controller_screen.dart:124-158`); the design doesn't say whether the bar and panel belong to the layer or the shell. `SafeArea` `:118` insets whatever is behind.
3. §2.7 hides the status panel "while a game is shown", but nothing tells the phone that yet; the panel follows `status.isHidden` only (`controller_screen.dart:342`, `game_controls.dart:167`), and `FrameView` is step 6.
4. The `Scaffold` paints an opaque full-screen Material (`:117`) and nothing paints under the controls, so "controls over a game" needs the game inside the body behind the layer (or no Scaffold background); the design doesn't name this.
5. `controller_screen.dart` (456) and `pad_widgets.dart` (421) already exceed the 400 hard limit, and `settings_screen.dart` (499) would take the opacity slider; guideline §3 wants the splits in the same job.
6. Opacity must not move rects or touch areas. Alpha per painter means an extra parameter in `_DpadPainter` `pad_widgets.dart:158-194`, `_FacePainter` `:270-369`, `_StickPainter` `stick_widgets.dart:158-203`, `_TiltPainter` `tilt_view.dart:91-126` and the pills `pad_widgets.dart:399-403`; an `Opacity` widget would also fade the press flash and the demo readout (**unsure** whether it changes hit tests — framework behaviour unchecked here).

## Questions

1. Where does `ControlsLayer` live: `controller_app/lib/src/ui/` (no new dependency) or `game_kit` (needs a `controller_app` → `game_kit` dependency the brief would have to name)?
2. Where is `overlayOpacity` persisted: `HostingSettings` in `game_kit` (host-side, no storage today) or a phone settings class in shared_preferences like `stickButtonSize`? §4 and §2.7 point at different homes.
3. Does the layer own the top bar (connection chip, mode switch, Settings/Diagnostics), the status panel and the demo readout, or only the mode controls? "Show on this device" (C34) implies the game fills the screen.
4. Is the opacity one `Opacity` over the controls `Stack`, or an alpha passed to every painter?
5. Should `phone_metrics` keep measuring the same body box when a game fills the screen, so session numbers stay comparable with controller mode?
6. Does step 4 add the "game is shown → hide the status panel" input now, or wait for `FrameView` in step 6?
