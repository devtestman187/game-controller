## Findings

- **must** packages/connection/lib/src/away_slots.dart:139 — the away player's `GamePlayer` is rebuilt from id, number, nickname, mode only, so `character` is dropped → a phone drops mid-round and every other phone's `players` list and `chars` show its number's default look until it returns (protocol.md §8d says "a player away whose phone dropped included"; server_game_frames.dart:~150 comment says "keeps theirs"). The test that should catch it still passes if broken: identity_rows_test.dart:53-63 asserts `forPlayer(2)`, which is also the character that phone joined with (no character sent). Fix: pass `character: player.character`, and give the test a non-default character.
- **must** packages/connection/lib/src/host_connection_pairing.dart:73 — a re-pairing hello's character is applied at once (`reserveCharacter(this, hello.character)`), not held during a round like `set_character` (host_players_broadcast.dart:55). A phone that drops and re-pairs mid-round changes a running round's look, which breaks the owner's Nov 23 answer and the rule in server_game_frames.dart `start`. protocol.md:§8d documents this as an exception (the "one exception" sentence) instead of the owner's rule. No test covers it. Fix: hold it with `heldCharacter` when `_roundRunning`, and correct §8d.
- **should** packages/protocol/lib/src/character.dart:107 — `Map<dynamic, dynamic>` parameter; review.sh `types` FAIL. Guidelines §2 "no dynamic". Fix: `Map<Object?, Object?>` (or `Map` validated per key).
- **should** packages/connection/lib/src/host_character_reservation.dart:49 and host_pairings.dart:184-190 — `recentCharacters` and `pickPlayer` count a dropped player's pick for one minute only, but `players` and the frame keep an away player until its round slot ends (away_slots.dart holds it past the 30 s grace). A phone that joins after that minute can get the away player's number and character, so two rows in `players` share both. Pre-existing for numbers; new for characters. Not run; verify with a clocked test (host up to 2 min, away slot still held).
- **should** packages/connection/lib/src/host_character_reservation.dart:42-53 with server_game_host.dart:332 — local players (keyboard, host phone's own player) wear `PlayerCharacter.forPlayer(number)` and are not in `taken`, so a phone can be given the same character as a local player. Owner answer Q4 says local players get `forPlayer(number)`; it does not say whether that default is reserved. Decide and pin, or mark as accepted.
- **should** packages/connection/lib/src/host_pairings.dart:87, host_server.dart:50 — the reserve-minute seam is a `DateTime Function()` clock, not the host's `nowMs` seam that the Nov 23 owner answer names (REVIEW Q2 "use the host nowMs seam"). Behaviour is right and tested (identity_reserve_minute_test.dart:17, :39), so it is a deviation from the stated instruction, not a bug. Either accept in the report or convert `lastSeen` to the host clock.
- **later** packages/protocol/lib/src/character.dart:144 — `playerColors` (colour literals) now sits in protocol; review.sh `color` FAIL. It moved from messages.dart (not new), and the palette is the look's concern. Cost to move now: small; cost later: a look change touches protocol.
- **later** packages/connection/lib/src/host_connection.dart:198 — `_handle` is 41 lines (review.sh func NOTE); the new `SetCharacterMessage` case added to it.
- **later** packages/connection/lib/src/host_server.dart:378, server_game_host.dart:357 — over the 300 aim, under the 400 hard limit; the next addition to either forces a split. host_server.dart's `part` list now has two extensions.
- **later** packages/protocol/lib/src/identity.dart — one file, `PlayerRow` typedef plus two public messages (`PlayersMessage`, `SetCharacterMessage`); guidelines §3 "one public type per file" allows a message and its enum only.
- **later** packages/connection/lib/src/host_server.dart:89 — `playerSource` is a public mutable callback, set by a `ServerGameHost` constructor and cleared in its `dispose`. A second game host on the same server overwrites it silently. Guidelines §2 "no global mutable callbacks".
- **later** packages/connection/lib/src/server_game_host.dart:326 vs host_players_broadcast.dart:15 — two row builders with different defaults (`_playerRows` defaults a missing character to `forPlayer`, `_sessionRows` omits the row). Also `_withoutCharacters` (host_players_broadcast.dart, end) and `_withCharacters` (server_game_frames.dart:153) each copy every FrameMessage field by hand, so a new frame field gets lost in one of them.
- **later** packages/connection/lib/src/server_game_frames.dart:72,110 — `_roundRunning` is set by `start` and cleared only by `end`. A game that stops without `endView` (game_session.dart:258 and :268 are the only callers) leaves every later character change held. Not a bug today; state in the report that every stop path calls endView.
- **later** packages/connection/test/frame_characters_test.dart:60 — the test named "already match ... sent with the same content" also passes if `_withCharacters` always rebuilt the frame, so it does not pin the shortcut. identity_host_test.dart:100 (round hold) never asserts that no `players` message goes out mid-round.
