# Milestone 0 checklist: Foundation and build pipelines

Copied from the PRD acceptance tests. Run it on a fresh install of the `m0` builds.

## Acceptance tests
- [ ] The controller APK installs and launches on the Android phone. *(Expect: landscape "Game Controller" screen, "Hello from android · protocol v1".)*
- [ ] The CI-built unsigned controller .ipa is signed with a free Apple ID, installs on the iPhone and launches. *(Expect: the same screen, "Hello from iOS · protocol v1". Follow docs/ios-setup.md.)*
- [ ] The TV app appears in the launcher and can be navigated with the remote. *(Expect: "Controller Test" banner in the launcher. In the app, left/right moves a thick focus ring between Input/Game/Haptics, center selects and shows "Selected: …", "Last key" updates, Back exits.)*
- [ ] CI is green, and a docs-only change does not start an iOS build. *(GitHub Actions "CI" green. Push a commit touching only `docs/` and confirm Codemagic starts no `ios-check-main` build.)*
- [ ] The protocol unit test passes locally and in CI. *(`cd packages\protocol; dart test`, and the "Test protocol" step in GitHub Actions and Codemagic.)*

## Extra checks (not in the PRD, quick)
- [ ] The TV app also runs on the laptop: `cd tv_test_app; flutter run -d windows`, and arrow keys + Enter behave like the remote.
- [ ] The Codemagic `ios-ipa` build finishes in well under 30 minutes (note the duration for minute budgeting).

## What can't be tested on emulators or Windows
| Area | Why | Where tested |
| --- | --- | --- |
| iOS install/signing | Needs a real iPhone and iLoader | iPhone |
| TV launcher banner and remote | Emulator is only a rough proxy | Physical Android TV |
| Android 16-specific behavior | Needs an Android 16 device | Android phone |
