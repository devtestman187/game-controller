# Milestone 1 checklist: Discovery, pairing and connection

Copied from the PRD acceptance tests. Run it with the `m1` builds: the iPhone `.ipa` from Codemagic (tag `m1`), the TV APK, and the Windows TV app. The Android phone items are marked *(deferred)* because Android phone testing is postponed (see `docs/decisions.md`).

Setup:
- TV: install the TV APK (`docs/building.md`) and open **Controller Test**.
- Laptop: `cd tv_test_app; flutter run -d windows` (or the release `tvtest.exe`), and follow the Windows Firewall steps in `tv_test_app/README.md`.
- iPhone: install `controller-unsigned-m1.ipa` with iLoader (`docs/ios-setup.md` steps 5–7). On first launch, allow the **local network** prompt.
- Everything on the same Wi-Fi (not a guest network).

## Acceptance tests
- [X] **Discover, pair, Connected (iPhone).** The TV appears under "TVs on this Wi-Fi". Tap it and type the 4-digit code from the TV. *(Expect: phone shows "Connected to Android TV" with a ping; the TV lists "iPhone XXXX" as **Connected** with a ping in ms.)*
- [ ] *(deferred)* The same on the Android phone.
- [X] **Wrong code is rejected.** Tap the TV and type a wrong code. *(Expect: "Wrong code…" on the phone; the TV never shows it as Connected and logs "wrong code (1 of 5)". After 5 wrong codes in a row the TV's code changes.)*
- [X] **Manual IP entry.** Type the address shown on the TV (e.g. `192.168.1.50:45780`) in "Or type the address" → Connect → enter the code. *(Expect: Connected, same as discovery.)*
- [X] **Wi-Fi off and on.** While connected, turn the phone's Wi-Fi off for about 10 s, then on. Don't touch the app. *(Expect: "Connection lost. Reconnecting…" with a rising attempt count, then Connected again without a code. The TV shows Disconnected, then Connected.)* Also try **Drop connections** on the TV: the phone reconnects within a second or two.
- [X] **iPhone local network prompt.** On a fresh install the prompt appears on first launch. Allow it. *(Expect: the TV appears in the list. Diagnostics → Local network permission shows **Allowed**.)* Optional: deny it in Settings → Privacy & Security → Local Network, then try manual entry. Diagnostics should show **Probably denied**.
- [X] **Simulated controller.** On the TV, press **Simulate controller**. *(Expect: "Simulated controller" appears as Connected with a ping and stays connected for at least a minute.)* From the laptop: `cd packages\connection; dart run connection:sim_controller --host <TV IP> --code <code>` prints CONNECTED and a ping every 5 s.
- [X] **Live ping on the TV.** The ping for each connected controller updates about once a second.
- [X] **Windows laptop as the TV.** Run the Windows app. The iPhone discovers it (named after the PC), pairs and shows Connected. *(Android phone: deferred.)*

## Extra checks (not in the PRD, quick)
- [ ] Relaunch the phone app while the TV app keeps running: it reconnects to the last TV with no code.
- [ ] Restart the TV app: the phone shows "The TV doesn't remember this phone…" and asks for the new code.
- [ ] Diagnostics → **Share** opens the share sheet with the report and log (AirDrop or Mail it to the PC if something fails).
- [ ] TV remote: arrows reach **New code**, **Simulate controller** and **Drop connections**, and OK presses them.
- [ ] The TV screen fits a 1080p TV with nothing cut off, and the Windows window still works when made narrow.

## Already verified on the PC (2026-10-24)
- 39 automated tests in `packages/connection` with real sockets: pairing, wrong code, code change after 5 wrong codes, token reconnect, host restart, heartbeat timeouts on both sides, replaced connections, version mismatch.
- The Windows TV app ran on the laptop. The command-line simulated controller was rejected with a wrong code, then paired over the Wi-Fi address (ping 2 ms), and an mDNS query found the advertised `Controller Test (<PC name>)` with its port and host ID.

## What can't be tested on emulators or Windows
| Area | Why | Where tested |
| --- | --- | --- |
| iOS local network prompt and Bonjour | Needs a real iPhone | iPhone |
| mDNS between devices | Emulators sit behind NAT | iPhone with the TV and the laptop |
| Wi-Fi drop and reconnect | Needs a real radio | iPhone |
| Windows Firewall prompt | Depends on this PC's settings | Laptop |

## Result (2026-10-24)
Passed on the iPhone, the TV and the laptop (Android phone deferred). Observation: ping usually 20–50 ms with occasional spikes over 100 ms. Likely cause: Wi-Fi power saving on the phone while traffic is sparse (one heartbeat per second). Nagle's algorithm is ruled out, because Dart's HTTP stack sets TCP_NODELAY on both ends. M2 adds lowest/average/highest ping over 30 s on both screens to measure it.
